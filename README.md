# word-ladder

A new four-letter word ladder every day: change one letter at a time to get from the start word to the target, and everyone who plays on the same date gets the same puzzle.

## What it does

Picks one start word and one target word from the 821-word connected core of a hand-written list of 874 common English four-letter words, using the current UTC date as the seed — so the puzzle is the same for everyone on a given date, and the header says which date and that it is UTC.

You type a word; it is accepted only if it is on the list, differs from the word above it in exactly one position, and has not already been used, and the rejection tells you which rule you broke.

The shortest possible solution is shown as `best possible: N moves` before you start — it is what the puzzle can be done in, not an allowance you have to stay inside — because the puzzle is generated by a breadth-first search from the start word, so a solution of exactly that length is guaranteed to exist. Once you have solved it, the status line and the line Share copies name that number with the same words, character for character: `solved in 5 moves · best possible 5`.

Undo takes back a rung at any point, including after you have solved it — the win belongs to the day, so walking the ladder back leaves the win and the streak standing — the label under the target goes back to `target`, because it names the word under it, and the status line keeps saying `solved today` — or just `solved` on a `?d=` replay, where the date at the top of the page is not today and there is nothing being saved for “today” to be a claim about.

Once the ladder reaches the target there is nothing left to add, so the input row is put away and Submit is spent with it. Two moves are left: Undo, which brings the row and Submit back, and Share.

Share copies one line you can paste anywhere — `word ladder 2026-08-30 · solved in 5 moves · best possible 5 · streak 1`, and the link to this page under it. A replay opened with `?d=` drops the streak clause, because a replay has no streak to claim. It says how your ladder went and never what was in it: no start word, no target, no rung, no letter, so someone who has not played today can read it without the puzzle being spoiled. Where the copy does not happen it puts the same line in a selected box on the page instead, says `copy this line — the browser refused the copy`, and you copy it yourself. Refused, not missing: opening this file directly rather than over `http://` is the common case, and there `navigator.clipboard` is present and it is `writeText` that comes back `NotAllowedError` — the same answer a permissions policy, an unfocused document or a stale gesture gives.

Reloading keeps the chain you were on, solved or not, and a solve on consecutive days builds a streak stored in your browser. Nothing is sent anywhere: no server, no accounts, no network calls at all. The page writes in exactly two places outside itself, both of them on your own machine: one `word-ladder.v1` entry in your browser's local storage, rewritten on every rung, which is what a reload comes back to; and the share line onto your clipboard, when you press the button that says so.

## How to run

Open `index.html` in any browser. There is no build step, no install, and no dependency — or just use the live demo above.

On a screen tall enough to hold it the whole game sits on one screenful and only the ladder column scrolls; on a short one — a phone in landscape — the page scrolls instead.

### Playing it, in order, from a cold load

- The input is focused when the page opens, so start typing the first word of your ladder and press Enter to play it.
- That first rung is also what makes Undo live — it is disabled on a fresh puzzle.
- From the input, Tab reaches Submit and, once a rung is on the board, one more Tab reaches Undo, which takes back the last rung; Shift-Tab walks back the same way. On a solved board Share joins the order after Undo, and the fallback copy box after that.
- Once the ladder is long enough to scroll, one Shift-Tab past the input reaches the column itself, which arrow keys then scroll — until it is, there is nothing hidden in it and it is not a stop. Turning a phone over is enough to make it one, and it becomes one there and then, without a reload.
- Keep typing and pressing Enter until you reach the target word at the bottom, where the label turns to `solved`.
- Case does not matter, accented letters are folded to plain ones, and anything that is not a letter is ignored as you type.

### What the solved board does

- A finished ladder has no next rung, so at that point the input row is put away — the last word you played sits directly above the target with no empty gap between them, and there is no field left to type a word into that could only be refused.
- Submit goes out of service with the field — there is nothing left for it to read, so it greys out and drops out of the tab order rather than sitting there looking live. It keeps its place in the row; a control that vanished would move the two beside it.
- Undo stays live and keeps the focus: it is the way back if you want to walk a different route, and the first Undo brings the input row, the caret and Submit all back. It does move — a third button arrives beside it, and the row divides three ways instead of two.
- Share appears next to it, and only there. It says `Copied` for a moment after it works, because a copy changes nothing else on the page and a button that gives no sign it was pressed gets pressed twice. Stepping off the target with Undo takes it away again: `solved in 5 moves` is a count of a ladder that reaches the target, and one Undo later there is no result to share.
- That is also how a solved board reloads — ladder, target, `solved`, a spent Submit, a live Undo and a live Share — with nothing focused until you Tab, because there is no field to put the caret in.

### Two extras worth knowing

- Adding `?d=2026-01-15` to the URL — any date but today — plays that date's puzzle as a replay: the header says `replay, nothing saved`, it never touches your streak, and nothing it does is stored. `?d=` for today is simply today's game, loaded and saved like any other. A `?d=` that is not a real date says so on the message line and shows today's puzzle.
- `tests.html` runs the assertion suite — determinism and a walked shortest solution across 30 consecutive dates, word-list integrity, the input-validation matrix, the streak arithmetic, the corrupt-storage cases, the share line and its clipboard fallback, and the rung labels — and prints the score. It drives the real page in an iframe, so unlike the game it needs a local server: run `python3 -m http.server` in this folder and open `http://localhost:8000/tests.html`.

## Why it exists

Seeded idea from the factory's warm-start pack (§16-P0): a daily puzzle small enough to finish in one sitting and old enough that a stranger already knows the rules. Word ladders are Lewis Carroll's, from 1877; this one just picks a fresh pair every morning and counts how many mornings in a row you showed up.

Word list: 874 common English four-letter words, written by hand in this repo from scratch — no dictionary file is downloaded, vendored, or fetched at runtime. No fonts, images, or data come from anywhere but these files.
